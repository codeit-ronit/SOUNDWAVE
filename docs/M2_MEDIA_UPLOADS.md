## Scope and storage

Active registered creators can upload **canonical PCM 16-bit WAV** to their own non-archived, non-removed draft chapters, view status, cancel/delete and preview technically validated audio. The allowlist is deliberately narrow: mono/stereo, 8–192 kHz, a 44-byte RIFF/fmt/data header, correct byte rate/alignment/length and complete PCM frames. Metadata/ancillary chunks, compressed WAV, MP3 and other input formats are unsupported. Every PCM sample is inspected with the existing bounded WAV analyzer; a signature alone never sets validated status. This is technical format validation, not malware certification, rights review or publishing approval. Default byte/rate bounds imply at most about 655 seconds of mono 8 kHz audio; actual sample rate and byte size determine duration.

`storage/local-private.js` uses a flat application-owned directory, generated 256-bit opaque keys and exclusive 0600 object creation. Client filenames, MIME, paths and URLs never select storage locations. The 0700 root must be outside `client/` and `server/public/`. Root/object symlinks, non-regular/multiply-linked objects, invalid keys and overwrite attempts are rejected; canonical root identity is checked on operations. No public static route points at this root. This assumes the service UID and host administrator are trusted: Node's path APIs are not a filesystem sandbox against a malicious process with the same UID. No S3 backend or multi-host shared-storage guarantee is claimed.

Upload input streams through a counting/hash transform into a file, without whole-file process buffering. Technical validation reads through a checked file descriptor and bounded 64 KiB sample buffers. Preview likewise streams an authenticated descriptor. Local file creation, bounded read and deletion are behind one storage adapter; a future remote adapter must define equivalent immutable write/access semantics rather than pretend remote objects are POSIX handles.

Configuration (Node 22):

| Variable                     | Default                                                     | Bound / purpose                                                                           |
| ---------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `PRIVATE_MEDIA_ROOT`         | `server/data/private-media` (absolute resolved module path) | Private filesystem directory; explicitly set for operational tooling                      |
| `UPLOAD_MAX_BYTES`           | 10485760 (10 MiB)                                           | 1–52428800; exact reserved bytes also enforced during transfer                            |
| `CREATOR_STORAGE_BYTES`      | 52428800 (50 MiB)                                           | 1–524288000; includes existing media, reservations and pending cleanup                    |
| `UPLOAD_TIMEOUT_SECONDS`     | 60                                                          | 1–120; transfer/validation timer, database operations retain existing query/lock timeouts |
| `UPLOAD_RESERVATION_SECONDS` | 600                                                         | 1–3600; time to start a reserved upload                                                   |

Compose mounts the same new `private_media` volume at `/app/private-media` in API/worker containers. The image initializes the mount point for non-root `node` with 0700 permissions. Existing PostgreSQL/Redis volumes are unchanged. Start the normal stack with documented `npm ci`, build/start or `docker compose up --build`; no object-store account is required. A single host/local volume is required; independent ephemeral API disks would lose uploads or disagree about bytes.

## Database and lifecycle

Additive PostgreSQL **016_private_media.sql** / SQLite **017_private_media.sql** add `private_media_assets` and `private_media_heads`. Asset UUIDs and object keys are generated by the server. Composite FKs bind exact story/owner and chapter/parent; head pointers must reference an asset for that chapter. Unique owner/request receipts and a partial unique in-flight-per-chapter index protect retries and admission. Quota/cleanup/owner indexes bound common lookups. Existing chapter audio URL/duration placeholders, story/chapter draft revisions and all listener relationships remain unchanged.

| State         | Meaning and allowed transition                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `reserved`    | Owner/quota/intent committed, no bytes yet; expires or single-use claim → uploading                                      |
| `uploading`   | Server lease token acquired atomically; one writer, bounded stream; success → quarantined                                |
| `quarantined` | Byte count/SHA-256 committed, private file awaits full technical validation; only trusted service completion → validated |
| `validated`   | PCM inspection succeeded; atomically selected as current chapter media; remains private and unpublished                  |
| `failed`      | Invalid/interrupted/expired/conflicting/unavailable upload; terminal, cleanup retried                                    |
| `deleted`     | Cancelled, replaced, explicitly removed or garbage-collected archived/removed chapter asset; terminal                    |

Assets retain bounded historical metadata/receipt identity (maximum 1000 retained upload records per creator). No asset/key is overwritten/reused. Deleted/failed bytes continue consuming quota until filesystem deletion succeeds. Only then is `storage_released=1`. No client chooses a lifecycle status or supplies a checksum as proof. Upload claims have a lease lasting transfer timeout + 30 seconds; deletion during upload invalidates attachment but retains the lease so cleanup cannot release a still-writing reservation prematurely. Handler termination clears the lease after closing its writer. A crashed writer is reclaimed after expiry. A severely paused or compromised same-UID process is outside this lease/host trust boundary.

All creator mutations follow account lock → owned resource checks within the same outer transaction. Quota sums are converted explicitly from PostgreSQL numeric aggregates to JSON-safe numbers. Reservation charges exact declared bytes once; size must fit both file and owner limits. Replacement temporarily charges old + new physical storage. Head revision is independent of draft metadata revision: initiating an upload captures both current chapter and media-head revisions. Completion rechecks active ownership, chapter availability, both revisions, lease and the original unexpired session. Logout completed before that final session check is denied; a request already authorized at that check can finish. A conflict detected at that final check rejects attachment; account locking orders suspension against writes. Concurrent owner operations serialize; no database transaction is held for the network transfer itself.

Successful replacement selects the new asset and retires the old one atomically; it never deletes the previous working audio before validation. Deleting a stale asset cannot clear a newer head. Deletion requires current asset revision; stale requests return 409. Metadata/revision/receipt records remain; no general privacy-erasure claim is made.

## Private REST contract

Base: `/api/creator/stories/:story/chapters/:chapter/media`. Session-derived active creator and exact owner are required on **all reads and writes**, including suspended/inactive denial and no staff bypass. IDs are canonical numeric story/chapter IDs and server UUID asset IDs. Writes reuse CSRF/origin protection and captured `X-Session-User`; reads are private/no-store and vary by Cookie. Existing API throttling applies; public audio range exemptions remain unchanged. No private catalog/Redis/PWA entries are introduced.

| Method/path                | Input / output                                                                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET base                   | `{headRevision, canPreview, current, recent, usedBytes, maxBytes, quotaBytes, acceptedType, processing}`; recent is at most five assets             |
| POST base                  | `{requestId, byteSize, expectedChapterRevision, expectedHeadRevision}`; first 201 `{asset,replayed:false}`, exact retry 200 `{asset,replayed:true}` |
| GET `/:asset`              | 200 `{asset}` including owned terminal state                                                                                                        |
| PUT `/:asset/bytes`        | Raw WAV/octet-stream body, not multipart; server counts actual bytes and hashes; 200 `{asset,replayed}` after validation                            |
| DELETE `/:asset`           | `{expectedRevision}`; 200 terminal asset acknowledgement; cleanup may remain pending                                                                |
| GET/HEAD `/:asset/preview` | Current, validated, non-archived/non-removed chapter audio only; authenticated 200/206/416; single safe ranges; no redirects or public caching      |

The owned serializer includes ID, asset revision, status, reserved/actual byte size, checksum, detected type, duration, validation version, expiry, controlled error code and cleanup-pending flag. It never returns filesystem paths, object keys, lease tokens or owner-selection fields. Unknown payload/query fields and client URLs/filenames/status/owner IDs are rejected. Header MIME is only an allowlisted hint; actual bytes must pass PCM validation. `Content-Length`, if supplied, must equal the reservation; chunked bodies are independently bounded. Zero, malformed/truncated/overlong and appended non-PCM-container data are rejected.

Errors retain `{error:{code,message}}`: 400 invalid input/length; 401 missing/expired session; 403 guest/inactive/suspended/CSRF/origin; equivalent foreign/missing 404; 409 stale media/chapter, pending/conflicting receipt/lease or quota; 413 streamed bytes too large; 415 unsupported body type; 422 invalid PCM; 408 timeout; 503 storage/recovery failure. No internal paths or stack traces are returned. An authenticated preview is not an authorization grant for public listener streaming or offline download.

### Retry and cancellation

The persisted reservation fingerprint includes owner UUID/request UUID, parent IDs, exact size and expected chapter/head revisions. Exact POST retries resolve the same asset even after completion/failure/deletion; changed intent returns `UPLOAD_REQUEST_REUSED`. Body transfer is single-use: one claim succeeds, concurrent attempts conflict; an already validated asset returns its existing result without re-ingestion/extra quota. A failed/deleted claim cannot be reused. There is no resumable/chunked upload session protocol or general exactly-once claim.

After an uncertain PUT, GET the asset/status before deciding. Reserved can be sent once; uploading/quarantined requires status recovery; validated is success; failed/deleted needs a new explicit reservation UUID. UI retries preserve the original reservation payload/key, lock file changes while uncertain and provide Refresh. Cancellation aborts browser transport; if bytes already committed, status may report success and explicit deletion is required. Server disconnect/timeout cleanup is independent of browser state. Tab-local keys are not a durable write queue; leaving/refreshing can lose them, but bounded recent/pending status and expiry expose/reclaim accepted work.

## Cleanup, import, backup and recovery

The existing worker runs a separate bounded cleanup loop every 30 seconds, at most 50 eligible rows per pass, even without media BullMQ enabled. Reserve also attempts bounded owner cleanup. It handles expired reservations/leases, failed/deleted bytes, and validated assets whose chapters were removed/stories archived. It rechecks rows under owner locks. Delete failures remain visible/charged and are retried; database rows do not vanish. Only DB-allocated tracked keys can be created, so interrupted writes remain discoverable without deleting arbitrary files by directory scanning. Temporary disk/permission failures do not falsely free quota. Operators must monitor free disk, cleanup backlog and worker health; per-user quotas are not a global disk admission system.

SQLite import **does not transport file bytes**. New media metadata/receipts are retained, but imported assets become failed `RESTORE_BYTES_REQUIRED`, get new opaque keys, release nonexistent target storage, and head pointers are cleared with a higher media revision. Existing target private chapter/media collections win as a whole. Ownership collisions abort; stale source media never overrides a current target asset. Re-upload is required after this database-only import; automatic byte-copy/revalidation is deferred.

PostgreSQL backup fingerprints now cover **26 tables**, including populated assets/heads. The manifest explicitly says private files are outside the database archive. For an operational full backup, drain/stop writers (API and worker), take a DB archive and matching private-volume snapshot, protect both as private data, and restore them together before re-enabling access. This campaign does not claim an atomic live cross-database/filesystem snapshot or a complete container-volume disaster-recovery drill. Old 21/22/24-table manifest inventories remain allowlisted, not arbitrary tables.

With an explicitly configured disposable/restored database and absolute storage root:

```bash
npm run media:private -- verify --confirm-operator
npm run media:private -- cleanup --confirm-operator
```

These commands load no dotenv and require explicit database settings and `PRIVATE_MEDIA_ROOT`. Verify streams all validated objects in 50-row pages, checks size/SHA-256 and exits nonzero if unavailable; it does not repair/change them. Cleanup performs one bounded pass. Keep a restored service unavailable until verify succeeds; for missing bytes, restore the matching volume or explicitly delete/re-upload. Database backups alone do not restore audio. Old seed/import/worker binaries must be drained before the additive migration rollout. No rollout was performed here.

## M2.5 handoff

Processing eligibility: current `validated` private asset, unchanged head, available owned draft chapter and matching checksum/validation version. Derive a stable job intent `private-audio:{assetUUID}:{sha256}:processor-vN`; persist/enqueue it transactionally through the existing outbox before claiming any reliable dispatch. No such FFmpeg jobs are produced yet. Asset revision/head revision are admission guards; SHA-256 and processor version identify immutable content work, not a user-supplied URL.

The next worker must safely open private bytes through the adapter, verify hash/lease/eligibility, use bounded subprocess argument arrays, publish derivatives only after rechecking unchanged identity/head, and implement retries/backoff, idempotent conditional output commit, failed-job visibility and kill/restart cleanup. Replacement/delete must invalidate stale work without deleting a new current asset. Only trusted processing services may advance lifecycle/derivative state; client receipt/completion cannot make content publishable. Add an explicit processing/ready/failed derivative model and resource/output-format limits; the current technical `validated` state is not publish-ready. Public catalog/streaming/offline policy remains denied until later tested publishing/rights gates.
